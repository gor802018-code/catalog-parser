# Парсер каталога: сбор карточек и выгрузка в Excel

Парсер собирает товары со страниц каталога и отдаёт результат в CSV и XLSX: артикул, наименование, цена, наличие, ссылка. Селекторы, пагинация, паузы и пути выгрузки описаны в `config/parser.json` — для нового сайта меняется только этот файл.

Демо работает на локальной HTML-странице: сбор карточек, разбор цен вида «2 349,50 руб.», удаление повторов по артикулу, выгрузка в два формата.

## Что умеет

- обход пагинации по шаблону `start_url` с `{page}`, остановка, когда карточки закончились;
- пауза между запросами, таймауты и повторы — без «залить сайт запросами»;
- разбор цен в русской записи: `1 500 ₽`, `2 349,50 руб.`, `990`;
- удаление дублей по артикулу с сохранением порядка;
- выгрузка в CSV (разделитель `;`, UTF-8 BOM — Excel открывает без танцев) и в XLSX с заголовками, автофильтром и закреплённой строкой;
- понятные ошибки: битый JSON, пустой селектор, страница без карточек.

## Структура

```
config/parser.json     адрес сайта, селекторы, пагинация, пути выгрузки
src/config.py          схема настроек на pydantic и их проверка
src/fetcher.py         загрузка страниц: User-Agent, таймауты, повторы, пауза
src/parser.py          разбор HTML, цены, дедупликация
src/storage.py         выгрузка в CSV и XLSX
src/cli.py             запуск: собрать -> разобрать -> сохранить
tests/fixtures/        тестовая страница каталога
tests/test_parser.py   тесты разбора и цен
tests/test_storage.py  тесты выгрузки
```

## Установка и запуск

```
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt

:: демо на локальной странице, без сети
.venv\Scripts\python -m src.cli --source tests\fixtures\catalog.html

:: боевой запуск по настройкам из config/parser.json
.venv\Scripts\python -m src.cli
```

Результат появляется в `output/catalog.csv` и `output/catalog.xlsx`.

Полезные флаги: `--config путь` — другой файл настроек, `--pages 5` — ограничить число страниц, `--source файл.html` — разобрать локальную страницу.

## Запуск в Docker

```
docker compose up --build
```

`config/` монтируется только на чтение, `output/` — на запись: правите селекторы и перезапускаете, не пересобирая образ.

Разово, без compose:

```
docker run --rm -v "%cd%\output:/app/output" catalog-parser:latest
```

## Проверка

```
.venv\Scripts\python -m unittest discover -s tests -t .
```

19 тестов: разбор цен (включая нечисловые и с неразрывным пробелом), разбор карточек, дубли, пагинация, CSV и XLSX. Прогон демо даёт 5 карточек на странице, одну отбрасывает как дубль и выгружает 4 записи.

## Как настроить под новый сайт

1. Открыть страницу каталога в браузере, посмотреть разметку карточки.
2. Прописать в `config/parser.json` селекторы `card`, `title`, `price`, `link`, `sku`, `availability`.
3. Заменить `site` и `start_url` (обязательно с `{page}`), выставить `max_pages` и `delay_seconds`.
4. Запустить `python -m src.cli` и проверить `output/`.

Если селектор не найден, парсер не падает молча: пишет, по какому селектору не нашлось карточек, и прекращает обход.

## Что важно помнить

- Собирайте только те страницы, которые сайт отдаёт без авторизации, и сверяйтесь с `robots.txt` и правилами площадки.
- Пауза по умолчанию — 1 секунда между запросами; для больших объёмов лучше поднять.
- Расписание (cron внутри контейнера или системный планировщик) — отдельная опция: парсер идемпотентен, повторный запуск просто перезапишет файлы.
